# 探索性试用记录

2026-09-23进行了两题、三种方法各单次生成的对照。输入、六份原样输出和版本记录在 [pilot.json](pilot.json)。这是一轮定性探索，不能推算总体胜率、获优概率或长期稳定性。

## 方法

三种方式：普通提示、已安装的goodWriter开发快照、Humanizer 3.0.0。各由独立子代理读取同一份请求执行，不读取其他输出。Humanizer由执行代理读取其公开源并报告版本；未固定仓库commit。

另一独立子代理只收到隐藏方法名的A/B/C候选和题目。两题标签映射不同，允许并列，不要求强行排名。揭示映射后结果为：

| 题目 | 观察 |
|---|---|
| 有完整材料的缓存优化总结 | goodWriter与Humanizer均保留证据、联系概念，整体接近；普通提示也准确，但带有提纲式标签 |
| 只有10/10结果的过强总结 | 三者均删除了无依据的个人成长与普遍正确性；goodWriter更短，普通提示更展开，Humanizer含部分写作自述 |

这些输出没有证明goodWriter优于其他方法。它们表明清晰的输入约束本身也能得到不错的结果，需要进一步验证技能在重复使用、模糊请求和不同课程中的增量价值。

## 限制

- 只有两道合成题，每题每种方法只有一次输出。
- 精确模型版本、采样温度与随机种子未记录，不能当严格可复现实验。
- 评阅者为模型子代理，没有真实教师评阅；定性盲评仍可能有偏差。
- 试用的是私用开发快照。公开alpha另外调整了默认自评分输出并补充文档，尚未整包复测。
- Humanizer面向广泛润色；此处题目限定在goodWriter的目标场景，不能代表对方全部能力。

## 下一轮怎样做

先选少量不同课程的真实授权或合成任务，冻结输入、技能版本、模型设置和评价维度。比较同一基础模型的普通提示、goodWriter及适合该任务的其他工具，多次独立运行；随机排列候选，分别记录事实错误、无依据经历、概念理解、表达与修改成本。由作者或教师在不知道方法名的情况下给出具体反馈。

不要用作者身份检测分数替代写作质量，也不要用内部自评分代替独立效果评估。新增案例可以扩展 [cases.json](../good-writer/evals/cases.json)，但不能把测试事实写入用户报告。
