# goodWriter

### 让实验报告写出你的思考

把实验记录、调试过程和结果对照，整理成能讲清**为什么这样做、结果说明什么、自己理解了什么**的中文报告。

[English](README.en.md) · [快速开始](#快速开始) · [完整示例](examples/reflection.md) · [技能正文](good-writer/SKILL.md)

实验做了不少，最后的总结却只剩“完成了任务，收获很大”？goodWriter 帮你从材料中找出值得展开的发现，把问题怎样被定位、方案为什么这样选择、结果如何联系课程知识写清楚，让读者看见你的判断过程。

适合中文实验报告、上机总结和课程设计。你可以让它起草全文，也可以只修改最后几段，保留关键数据和自己的表达习惯。

## 看看总结可以怎样写

**实验记录**：最初以为磁盘读取慢，分项计时发现重复计算才是瓶颈。固定输入、只改缓存，耗时从4.8秒降到1.6秒，内存从18MB升到41MB，输出相同；只测试了一个输入规模。

**原稿**

> 通过本次实验，我深刻认识到了优化的重要性。经过不懈努力，我显著提升了性能，充分证明缓存是一项卓越而普适的技术。

**使用 goodWriter 后**

> 结果显示，耗时由4.8秒降至1.6秒，内存由18MB升至41MB，输出保持相同。这个对照让我更具体地理解了性能优化的基本思路：先用测量定位问题，再通过控制变量验证方案；缓存带来的收益是用额外内存换取计算时间，并不意味着在所有场景下都一定更优。

这一版保留了数据，也说明了选择依据、时间与空间的权衡，以及结论的适用范围。

## 快速开始

已安装 Node.js 时，可以通过 [Skills CLI](https://github.com/vercel-labs/skills) 添加：

```sh
npx skills add https://github.com/g-sleeper/goodWriter/tree/main/good-writer
```

然后在 Codex 中使用：

```text
用 $good-writer 修改我的实验报告，重点打磨最后的总结。
根据这些记录写清问题解决的思路、知识理解和收获，保留我的语气与实验数据。
```

一起提供题目要求、实验条件与结果、原稿，以及你实际遇到的问题或做过的选择。几条简短笔记也有用，不必先整理成完整报告。

## 按你需要的范围修改

| 你遇到的问题 | 可以这样要求 |
|---|---|
| 总结像流水账 | “只改总结，把关键发现与课程知识联系起来。” |
| 调试记录很零散 | “整理问题、排查、修改与验证过程，解释每一步的理由。” |
| 文字太僵硬 | “保留数据和术语，让表达更自然，贴近我的原稿。” |
| 不确定有没有讲清楚 | “从阅卷者角度检查：哪些认识有依据，哪些段落还在说空话？” |

## goodWriter 关注什么

**发现背后的判断。** 从反例、对照或关键选择中提炼值得讲清楚的问题，而不仅停留在最终分数。

**知识之间的联系。** 解释实验现象怎样体现课程概念，以及不同题目、方法或指标之间的关系。

**有细节的个人表达。** 保留你的真实选择与认识，不把每份报告改成同一种“深刻体会”模板。

**可以复用的方法。** 把收获落到下次遇到类似问题时，能够采用的检查、比较或验证方式。

默认给出修改后的正文；需要逐段评审或评分时再提出。只提供成绩而没有过程材料时，它会先写有依据的结果结论，帮助你补齐形成个人心得所需的信息。

## 项目进展

当前为 **Alpha**，已在 Codex 子代理环境中进行合成案例试用。测试方法、原样输出和适用边界见[评测记录](benchmarks/README.md)。核心技能是 Markdown 指令与参考文件，不需要 API key；Word、PDF 等排版由使用环境中的文档工具负责。欢迎反馈其他宿主中的使用情况。
