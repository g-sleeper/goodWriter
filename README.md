# goodWriter

把实验记录写成有证据、有理解、有个人判断的中文报告。

[English](README.en.md) · [技能正文](good-writer/SKILL.md) · [示例](examples/reflection.md) · [试用记录](benchmarks/README.md)

**状态：Alpha。** 当前重点是中文课程实验、上机报告和学习反思。已有合成案例试用，尚无真实教师评分效果验证。

## 它解决什么问题

实验做完了，结尾却只剩“通过本次实验，我深刻认识到了……”。goodWriter 帮助把记录中的关键选择与发现讲清楚：为什么这样判断，怎样验证，它与课堂知识有什么联系，下一次怎样使用这项认识。

适合：

- 根据已有实验记录起草报告；
- 只重写最后的总结与心得；
- 保留数据和术语，修改僵硬、夸张或空泛的中文；
- 审阅论证、知识理解与结果是否相符。

## 一个短例子

**已有材料（合成示例）**：起初以为磁盘读取慢，计时发现重复计算才是瓶颈。固定输入，只改缓存：耗时4.8秒降到1.6秒，内存18MB升到41MB，输出相同，只测过一个输入规模。

**原稿**：

> 通过本次实验，我深刻认识到了优化的重要性。经过不懈努力，我显著提升了性能，充分证明缓存是一项卓越而普适的技术。

**改写节选**：

> 这个对照让我更具体地理解了性能优化的基本思路：先用测量定位问题，再通过控制变量验证方案；缓存带来的收益是用额外内存换取计算时间，并不意味着在所有场景下都一定更优。

完整输入与输出见[示例](examples/reflection.md)。这是一次实际试写的节选，不能证明每次生成都能达到相同效果。

## 开始使用

下载并解压本仓库，或克隆后进入仓库目录：

```sh
git clone https://github.com/g-sleeper/goodWriter.git
cd goodWriter
```

然后安装到 Codex：

```sh
mkdir -p "$HOME/.codex/skills"
cp -R good-writer "$HOME/.codex/skills/"
```

如果已有同名技能，先自行比较和备份，不要直接覆盖。重新加载技能或开始新会话后，使用：

```text
用 $good-writer，根据我的题目、实验记录和原稿修改报告。
重点改最后的总结，保留我的表达习惯，不改实验数据。
```

最有用的输入是题目要求、实验条件与结果、真实问题或设计选择、原稿。没有完整调试日志也可以使用；只提供最终成绩时，只能先形成有限的结果结论。

核心是 Markdown 指令与参考文件，不需要 API key、脚本或联网服务。已在 Codex 子代理环境试用；其他支持 Agent Skills 的宿主可尝试载入 `good-writer` 文件夹，尚未逐平台验证。Word/PDF 排版由使用环境中的文档工具负责。

## 和通用润色工具有什么不同

goodWriter 着重把记录连接到课程概念、问题解决与学习收获。通用润色工具更适合广泛文体的句子和段落修改，两者范围不同。本项目没有证明效果优于 Humanizer 等工具。

写作遵循几个简单原则：

1. 先核对材料，再组织主线和表达。
2. 从关键反例、对照或选择中提炼认识。
3. 区分实际观察、作者自述、解释假设和后续计划。
4. 保留自然的个人语气，不把所有报告写成同一套心得模板。
5. 先交付清洁正文；用户要求审阅时，再提供评语或评分。

## 目前的证据与局限

- 有四类合成案例覆盖总结、材料不足、数字保留和过强结论；开发过程中曾发现并修正无依据成长叙述。
- 有两题、三种方法各单次生成的探索性对照，结果见[试用记录](benchmarks/README.md)。样本很小，不是稳定性或总体优势证明。
- 没有真实教师盲评或跨模型、多次采样的效果结论。
- 不保证优秀称号、特定分数、作者身份判断或所谓 AI 检测结果。

## 贡献一个有价值的案例

欢迎提供自己有权公开的匿名或合成材料：任务要求、最小输入、当前输出、具体问题、预期改进，以及模型和版本。没有许可时，请勿提交其他同学的作业、教师评语截图、学号或私人记录。

优先欢迎不同课程的例子、失败案例、跨模型测试和对中文行文的具体修改建议。不要只报一个总分；指出哪一句改变了事实、哪段仍然空泛，会更有帮助。
