# 优秀样例的可迁移经验

根据用户提供的课程优秀报告及教师评语提炼。已读本课程第二次上机九份报告，以及第一次上机三份报告；只保存写作经验，不打包同学原文、代码、截图和身份信息。获优是选择结果，不证明每个公式、实验和写作做法都正确。

## 观察到的优势

| 样例中的有效做法 | 为什么有帮助 | 在新报告里怎样用 |
|---|---|---|
| 开头交代各题如何递进 | 老师快速理解全文主线 | 说明每项任务新增的约束或解决的子问题，避免虚构线性关系 |
| 按题记录具体错误、检查与修复 | 让解决过程可见 | 从真实记录选关键过程，不为每题强凑一次失败 |
| 用“通过测试却仍输掉游戏”等现象统合结尾 | 引出实现正确、模型假设与实际效果的区别 | 选择本题确有证据、能连接多个概念的问题 |
| 用相同场景下不同行为解释算法差别 | 让定义变为可理解的判断 | 先展示行为，再解释假设；不要只替换 max/min 等术语 |
| 区分单步与整局、理论与实测 | 体现指标选择意识 | 交代统计对象，解释为何同一优化在不同口径下收益不同 |
| 解释特征、权重和行为副作用 | 展示设计判断而非参数清单 | 说明每项解决什么问题、过大过小会怎样、有什么计算成本 |
| 总结联系状态设计、问题松弛与正确性边界 | 从实现升到课程理解 | 写清抽象保留了什么、舍弃了什么、为何仍支持结论 |
| 将经验变成下一次的检查顺序 | 收获可迁移 | 写遇到何种问题时先检查什么，再用什么证据确认 |

语言上的共同优势是具体、解释性强、能看见作者的决定。第一人称有时有效，但客观的“综合结果分析”也有获优样例，不能把个人感言设成唯一合格形式。

## 当前教师反馈能支持到什么程度

已见评语包括“问题记录很细致”“通过实验加深理解”“思考很深入”“思路清晰”“时空复杂度都分析了”，另有评论明确提到动手帮助理解课堂剪枝知识。它们支持重视问题过程、理论联系和可读性。

第一次作业的评语还在肯定较少扩展节点后追问时间开销，提醒写作不能只报亮眼单指标，也要交代实际代价。

未见正式权重或未入选者的直接扣分说明，因而不能断言总结占多少分，也不能以获优名单作严格技术排名。以上偏好只作当前课程的校准材料；换老师或课程要重新看要求，不自动沿用。

## 不应照学的地方

- 范文中也有剪枝等号前后矛盾、层次标注笔误和无前提复杂度。技术结论回到题目、代码与可靠理论核对。
- 某些报告提到可采纳性、一致性等术语，却未证明它们适用于当前评价函数。概念越高级越需要说明关系，不能用术语装饰总结。
- 少量对局、未交代条件或多个改动一起发生时，不用“充分证明”“稳定最优”描述结果。
- 展望中的在线学习、强化学习、缓存等方案不等于已实施成果。保留为有条件的后续选择，避免大而空的路线清单。
- “算法像眼睛”“让机器拥有人的判断”等比喻只可辅助理解，不能替代机制解释。
- 篇幅、公式数、截图数、满分次数未被证实决定优秀。好的短报告也可能通过清晰的知识关系完成任务。

## 对原用户报告的针对性教训

原报告的强项是等值剪枝反例、距离与奖励改动的对照、失败方向记录。弱项是结尾重复性能与评分机制，以及把样本最好值和原因假设升级为理论结论。

因此借鉴应保留实验证据，把它们提炼成理解和方法，同时缩小过强结论。不要为了更像范文，删除已有严谨分析、添加虚假的“最初不懂”，或抄其他同学的学习轨迹。
